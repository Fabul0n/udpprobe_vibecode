# Отчёт проверки udpprobe

Проверено в Linux x86_64, Rust 1.97.1, edition 2024. Измерения ниже выполнены
release-бинарником на IPv4 loopback. Это проверка инструмента, не исследование
внешнего сетевого пути. Полные результаты: [loopback-report.json](loopback-report.json).

## Автоматические проверки

Успешно выполнены:

```text
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo build --release --locked
```

24 теста: 4 библиотечных, 3 CLI unit-теста, 13 сценариев с виртуальной сетью и
4 интеграционных теста бинарника. Реальный IPv6 loopback в текущем окружении доступен,
его тест прошёл. CI добавлен, но удалённый запуск CI не выполнялся.

Виртуальная сеть проверяет независимый учёт send errors, потерь, duplicates,
reorder, late responses и invalid responses. Есть тесты границы размера, token,
неполных/неизвестных заголовков, лимитов сервера, ограниченной таблицы адресов,
отмены, пустой RTT-выборки и nearest-rank percentiles.

## Контрольный эксперимент

Сервер запущен на `127.0.0.1:0`; выделенный ОС порт сохранён в JSON.
Параметры: `--max-echo 1600 --rate-limit 10000 --token 42`.
Клиенты использовали тот же token и `--timeout-ms 100` (кроме проверки отмены).

| Сценарий | Параметры | Результат |
|---|---|---|
| train | size=1200, count=20, rate=100pps | 20 отправлено, 20 уникальных ответов |
| mtu | min=512, max=2048, count=3, rate=100pps, repeats=2 | 16 серий; 48 отправлено, 42 ответа, 6 без ответа |
| sweep | size=1200, count=10, rates=50/100/500pps, repeats=1 | 30 отправлено, 30 ответов |
| echo-small | size=2048, count=3, rate=50pps | 3 отправлено, 3 ответа размером 31 байт |
| Ctrl-C | count=10000, rate=100pps, прерывание через ~50 мс | частичный JSON, cancelled=true, exit code 130 |

Все 6 проб без ответа относятся к размеру 2048 без echo-small. Серверные счётчики:
106 датаграмм получено, 100 ответов отправлено, 6 oversized, 0 rate_limited,
0 malformed, 0 unauthorized, 0 send_errors. Отдельный fake-network тест подтверждает,
что ограничение 50 ответов/с при 100 запросах/с также создаёт наблюдаемые потери.

Таким образом, здесь причина пропусков известна: серверный max-echo. По клиентскому
порогу нельзя было бы объявить MTU=1600. Полноразмерные запросы 2048 с echo-small
успешны, поскольку сервер ограничивает размер **ответа**.

RTT и фактический темп в JSON — один конкретный запуск; они зависят от планировщика.
Проверка не подтверждает поведение на внешних маршрутах, обнаружение fragmentation
или точность генерации 100000 pps. DF/PMTUD не настраивается. ThreadSanitizer не запускался.

Публикация репозитория на GitVerse и приглашение участника из слайдов не выполнялись.
